# 실패 때문에 기억과 절차가 바뀌는 전체 예제

이 예제는 합성 경험을 사용하는 실제 SQLite 실행이다. 사람의 의미 판단을 명시적으로 입력하며 자동 해석 성능을 보여주는 예제가 아니다. [실행 코드](../examples/persistent-demo.mjs)의 저장·갱신 결과를 단언으로 확인한다.

```bash
node examples/persistent-demo.mjs --explain
```

## 처음에는 이렇게 이해한다

첫 경험은 “필요한 입력이 있는 일반 요청을 이 절차로 완료했다”다. 초기 판단은 “이 절차로 일반 요청을 완료할 수 있다”, 의존 절차는 “입력 조건을 충족할 때 이 절차를 사용한다”다. 처음에는 일반 요청이라는 넓은 조건으로 검토한다. 이는 나중에 반례로 수정할 가설이며 일반적 효과를 이미 입증했다는 뜻이 아니다.

첫 경험을 지지 관계로 연결하고, 의존 절차는 판단을 전제로 연결한다. 성공 보고서의 요약은 같은 사건 식별자로 등록한다. 별도 원문이지만 별도 성공은 아니다. 그 뒤 독립된 두 번째 시험과 사용 사건을 기록한다.

| 단계 | 독립 지지 | 독립 반박 | 사용 | 판단·절차 검토 |
| --- | ---: | ---: | ---: | --- |
| 첫 성공과 검토 | 1 | 0 | 0 | 최신 |
| 같은 사건의 재인용 | 1 | 0 | 0 | 재검토 필요 |
| 독립된 두 번째 성공 | 2 | 0 | 0 | 재검토 필요 |
| 사용 기록 | 2 | 0 | 1 | 재검토 필요 |
| 새 실패 | 2 | 1 | 1 | 재검토 필요 |
| 조건과 관계 정정 | 2 | 0 | 1 | 재검토 필요 |
| 근거 재검토 | 2 | 0 | 1 | 최신 |
| 저장소 재시작 | 2 | 0 | 1 | 최신 상태 유지 |

재인용도 새 관계가 생겼으므로 검토 토큰은 달라진다. 근거 수가 같다고 새 관계를 읽은 것으로 처리하지 않는다. 이 예제는 보수적인 검토 정책을 보여주며 사람이 실제 모든 관계를 제대로 검토했다는 사실은 단언 검사만으로 증명하지 못한다.

## 실패가 들어오면

“필요한 입력이 없는 요청에서는 실패했다”는 새 경험을 넓은 초기 판단의 반례로 연결한다. 그 판단에 의존한 절차도 재검토 상태가 된다. 성공 수에서 실패 수를 빼서 하나의 신뢰 점수를 만들지는 않는다.

성공 두 건과 실패 한 건의 원문을 비교하면 조건이 다르다. 그래서 기억을 “필요한 입력이 있을 때 일반 요청을 완료할 수 있다. 입력이 없는 요청은 이 판단의 적용 범위 밖이다”로 수정한다. 의존 절차도 “필요한 입력을 먼저 확인하고, 없으면 확보하거나 다른 방식을 선택한다”로 수정한다.

성공 근거를 새 조건에 대해 다시 확인하고 각 지지 관계의 조건도 갱신한다. 기존 실패는 새 조건을 시험한 사건이 아니므로 현재 판단에 대한 반박 연결을 철회한다. **실패 원문은 그대로 남고, 초기 넓은 판단을 반박했던 연결과 변경 이유는 이력에 남는다.** 반례를 숨겨 신뢰도를 높이는 작업과 구별된다. 조건을 결과에 맞춰 좁힌 가설의 독립 검증은 여전히 필요하다.

문장을 고쳤다는 이유만으로 검토 최신 상태가 되지 않는다. 기억과 의존 절차, 활성 근거를 읽고 별도 검토를 확정한다. 재시작 후에도 조건·이력·요청 결과가 유지되는지 확인한다.

## 실제 API의 흐름

기존 기록을 읽을 때 돌려받은 `read_token`은 당시 판단의 버전이다. [실행 코드](../examples/persistent-demo.mjs)에는 새 원자료와 비어 있지 않은 의미 변경을 포함한 전체 호출이 있다.

```js
const read = store.inspect('method');
const plan = prepareEvolution(store, {
  request_id: 'a-unique-change-id',
  actor: 'authenticated-reviewer',
  recorded_at: new Date().toISOString(),
  reason: '실패 원문과 성공의 입력 조건을 비교해 적용 범위를 수정했다',
  read_set: { method: read.read_token },
  memories: [{
    id: read.id, kind: read.kind, state: read.state,
    text: '필요한 입력이 있는 경우에 이 절차를 사용한다.',
    context: { ...read.context, condition: 'required input available' }
  }]
});
const receipt = store.apply(plan);
```

이 짧은 호출은 본문 갱신 계약만 설명한다. 실제 예제는 의존 절차와 관련 관계도 같은 변경안에서 갱신한다. 관계를 참조하면 끝점과 원문에도 실제 읽은 토큰을 제공해야 한다. 판단을 준비하면서 최신 토큰을 새로 얻어 과거 판단을 덮어쓰는 것은 거부한다. 단일 작성자 예제의 읽기 보조 함수는 다른 작성자가 있는 업무에서 의미 검토를 대체하지 않는다.

검사 결과의 `assertions: passed`는 중복·영향 전파·상태·이력·재시작 규칙이 지켜졌다는 뜻이다. 자연어 해석의 정확성, 실제 절차의 효과, 다른 기억 시스템보다 높은 성능을 뜻하지 않는다.
