# 같은 입력을 사용하는 비교

비교 목적은 기억 수를 늘리는 것이 아니라 조건·반례·정정이 다음 사용에 전달되는지 확인하는 것이다.

동일 원문의 식별자와 SHA-256, 단계, 질문, 검색어, 반환 개수·문자 예산을 실행 전에 고정한다. 각 방식의 방법도 명시한다. 결과에는 원문과 일치하는 근거 위치, 반환 내용, 예산 때문에 보류한 후보, 준비·검색·반환 처리 시간이 남는다. 질문이 바뀐 실행이나 입력이 다른 방식은 거부한다.

```sh
node examples/comparison.mjs
node --test evaluation/compare.test.mjs
```

합성 예제는 영속 코어의 실제 여덟 단계를 실행하고 원문 검색, 원문 전수 읽기, 초기 그대로인 기억, 갱신한 기억을 비교한다. 전수 읽기는 모델을 사용하는 능동 검색 에이전트가 아니다. 갱신하지 않은 기억의 검토 상태는 초기 시점에 한정된다. 반례·조건 변경·의존 절차 정정·재검토·재시작을 같은 입력으로 읽을 수 있다. 목표는 방법의 실패만으로 폐기되지 않는다.

반환에는 기억 본문·조건을 전부 유지한다. 원문 구간은 식별자·판본·문자 위치·인용 지문으로, 기억에 붙은 관계는 종류별 개수를 가진 색인으로 알린다. 기억 식별자로 상세를 열어 관계의 식별자·버전·방향·종류를 읽는다. 관계 조건과 실제 인용은 관계 상세·원문에서 읽는다. 참조 목록만 보고 관계의 적용 여부를 확정하지 않는다. 원문을 삭제하거나 인용을 변경하지 않는다. 의존하는 모든 인용을 매번 복제하지 않고 필요할 때 원문을 따라 읽는다. 두 방식에 같은 표시 규칙을 적용한다. 응답 문자 예산이며 모델 토큰 수나 실제 사람의 읽기량은 아니다. 원문 전체의 지문 검사량과 시간도 별도로 기록한다.

실제 조직 자료는 공개하지 않는다. 어댑터는 고정된 입력 집합에서 결과를 얻고 원문 위치 검사에 쓰는 읽기 함수를 제공한다. 비교 실행은 읽기 전용으로 수행하며 원본이나 기억을 편집하지 않는다.

실행기는 의미의 정확성, 독립 평가, 이용자의 작업 시간, 이전 기억 구성·재검토를 포함한 총비용을 자동 채점하지 않는다. 미측정 값은 null로 둔다. 합성 자료 작성자 자신의 결과로 우위를 주장하지 않는다. 긴 원문이나 후보가 예산을 넘으면 보류 수를 공개하고 별도 의미 평가와 총 관리 비용을 추가해 판단한다.
