# 평가와 안정화 조건

## 형식·전이 검사

공개 참조 검사기는 합성 데이터로 연결 경계, 정확한 원본 구간과 해시, 출처 집단 중복, 조건 차이, 상반된 근거, 철회, 간접 영향, 새 관계에 따른 검토 만료, 순환과 일괄 검토, 재시도와 버전 충돌을 검사한다. 전체 교환 파일을 읽는 메모리 내 예제이며 인증·DB 복구·분산 운영 검증은 포함하지 않는다.

검토는 변경과 분리된 요청으로 처리한다. 순환 의존은 해당 집합의 모든 기억을 같은 요청에서 검토할 수 있다. 요청 시작 시 모든 토큰을 확인하고 함께 갱신한다. 집합 밖의 미검토 전제를 남겨둔 채 최신 검토로 확정하는 것은 거부한다. 순환 전체를 검토했다는 사실 자체가 외부 근거나 논리적 정당화를 제공하지 않는다.

## 실제 위키의 비교 실험

동일 입력 전체와 동일 질의 집합을 고정해 다음을 비교한다. 실제 자료는 공개 레포에 올리지 않고 권한 있는 평가 환경에 둔다.

| 비교군 | 구성 | 확인하려는 것 |
| --- | --- | --- |
| A | 기존 문서와 링크 및 원문 검색 | 현재 방식의 기준 성능 |
| B | 원문 그대로의 능동 검색 | 구조화 자체가 필요한 범위 |
| C | 기억·관계를 만들되 갱신 없이 조회 | 연결 표현의 효과 |
| D | 기억·관계와 근거 있는 갱신 | 상태 갱신이 추가로 만드는 효과 |

먼저 기존 위키의 전체 입력 목록과 원본 버전을 고정하고 모든 입력을 기억 채택·기존 기억 변경·근거만 보존·미확인으로 분류한다. 불편한 문서 유형이나 반례를 제외하지 않는다. 질의와 평가 기준은 결과를 보기 전에 고정한다. 전체 입력을 일부만 처리했다면 전체 평가라고 부르지 않는다.

평가에는 단순 사실 검색뿐 아니라 시점 변경, 새 반례, 다른 조건의 성공, 원자료 정정, 재인용, 미션과 수단의 구분, 관련 정보 없음, 접근 권한 철회, 긴 절차의 조건 보존, 직접 연결하지 않은 새 반례 발견을 넣는다. 모델이 만든 연결과 기억은 독립 검토자가 원문 대조한다. 형식 검사와 의미 검토를 따로 보고한다.

측정할 결과는 근거 일치율, 조건·부정·예외 보존, 최신 상태 준수, 반례 발견률, 잘못된 기억 정정 후 판단 변화, 모를 때의 보류, 사용자의 실제 판단 시간과 오류다. 입력 처리+조회+재검토의 총 비용·시간·메모리도 함께 측정한다. 검색 속도만 좋아지고 정정 비용이 커지는 경우도 공개한다.

LongMemEval은 정보 추출·다중 세션 추론·시간 추론·갱신·보류를 평가하는 참고다. 대화 기억 성능을 조직 위키 전체의 유효성으로 확대하지 않는다. ReFind처럼 원문 검색이 강한 경우 그래프에 유리하도록 비교군을 약화하지 않는다.

## 안정화 관문

1. 코어의 모든 규범에 긍정·부정 사례와 검사 가능/의미 판단/운영 검증의 구분이 있다.
2. 최소 두 독립 구현이 같은 데이터와 토큰을 교환하며 조건·상태·근거를 잃지 않는다.
3. DB 구현이 동시 변경, 시간초과 후 결과 조회, 중단·재시작, 작업 중복, 권한·삭제·복구를 검증한다.
4. 전체 위키 비교에서 사전 지정 질의의 의미 정확성·정정 가능성·총 관리 비용을 확인한다.
5. 외부 검토에서 반례·확장·호환성 문제를 공개 논의하고 규격을 수정한다.

이 관문 전에는 공개 초안이다. 현재 공개 예제로 실제 위키보다 우수하다거나 최고 수준의 성능을 입증했다고 말하지 않는다.

출처: [LongMemEval](https://arxiv.org/abs/2410.10813), [ReFind](https://arxiv.org/abs/2608.12888).
