# 실제 기억 관리 시스템 구조

공개 코어는 기억 관리의 저장·갱신·회상을 맡고, 적용 환경의 어댑터는 기존 원자료의 식별·접근 권한과 화면을 맡는다. 추출 모델이나 특정 위키에 종속시키지 않는다. 의미 판단은 변경안으로 명시하며 자동 파싱을 의미 검토로 표시하지 않는다.

## 같은 저장소의 두 관리 모델

기존 문서·원자료를 변경하지 않고 새 memory_* 테이블을 추가할 수 있다. 원본이 수정될 때 과거 출처가 사라지지 않도록 불변 버전으로 보존한다. 공개 시스템은 SQLite를 첫 구현으로 제공하지만 명세 자체가 SQLite를 요구하지 않는다. 기존 문서와 새 기억은 각각의 관리 모델이며 새 기억이 기존 문서를 덮어쓰지 않는다.

| 저장 대상 | 역할 |
| --- | --- |
| sources | 불변 원본 버전과 출처·범위·이전 문서의 상태 |
| memories | 현재 의미, 종류, 조건, 적용 범위, 버전과 검토 |
| links | 기억과 원본 사이의 근거, 기억 간 지지·반박·전제·정정·탐색 |
| changes | 변경 요청과 결과. 시간초과 후 요청 ID로 확인 |
| units | 모든 원자료 구간의 처리 여부와 이유 |
| usage | 실제 사용 사건. 근거 집계와 구별 |

## 의미와 관계의 변화

입력 원문을 문장별로 잘라 현재 기억으로 자동 채택하지 않는다. 기존 의미와 조건을 읽고 유지·지지·반박·조건 추가·정정·새 설명·새 관계로 해석한다. 같은 의미의 재사용은 같은 기억에 근거를 추가한다. 서로 다른 의미가 되면 새 버전 또는 새 기억과 정정 관계를 사용한다. 관계만 잘못됐으면 해당 관계만 철회한다.

새 설명은 후보 상태로 만들 수 있다. 원문과 기존 맥락을 검토한 판단만 현재 이해로 전환한다. 목적·원칙의 채택 권한은 환경의 정책을 따르며 빈도와 성공률로 자동 변경하지 않는다. 관계의 지지·반박은 정확한 원본 구간과 설명을 가진다.

## 국소 변경과 영향

변경안은 읽고 판단한 기억·관계·원본의 버전을 고정한다. 같은 요청 ID의 같은 내용은 이전 결과를 반환하며 다른 내용은 거부한다. 준비 중 다른 변경이 생기면 충돌로 처리한다. 본문·관계·구간 처리·영향 상태·변경 결과를 같은 거래에서 저장한다.

전제·지지·반박·정정 관계를 따라 재검토를 전달하고 단순 탐색 관계로 신뢰를 전파하지 않는다. 순환에서는 반복 방문하지 않는다. 직접 연결뿐 아니라 간접 전제와 관계 집합 변화를 검토 토큰에 반영한다. 원문 버전 변경은 관련 기억을 최신으로 자동 확정하지 않는다.

## 회상과 결과 피드백

회상은 키워드 검색에서 시작해 관계를 따라 전제·반례·정확한 원본을 읽는다. 유사도와 연결의 근거 타당성을 구분한다. 최신 검토·적용 조건·반례가 함께 제공돼야 한다. 문서 원문 검색도 별도 경로로 유지한다. 이후 실제 결과는 새 원본으로 기록해 기존 기억의 의미·조건·관계에 다시 반영한다.

사용 사건은 활동량이며 독립 근거가 아니다. 같은 결과를 다시 요약해도 근거가 늘지 않는다. 같은 조건의 독립 경험만 지지·반박 집계에 반영한다. 모호한 독립성은 미확인으로 남긴다. 나중에 독립성이나 경험 시점을 확인하면 원문 본문을 바꾸지 않고 출처 메타데이터를 버전으로 정정한다. 사건 집단의 병합·분리가 집계를 바꾸므로 관련 기억을 재검토한다.

## 적합성과 배포

원자적 실패, 동시 수정 충돌, 요청 중복, 재시작·복구, 원본 철회, 새 관계에 따른 검토 만료, 검색·그래프 회상, 전체 구간 처리 여부를 실제 저장소에서 시험한다. 합성 자료를 공개하고 실제 조직의 자료는 해당 권한 경계 안에서만 확인한다. 코어 구현과 업무 자료의 의미 정확성 검증은 구분한다.
