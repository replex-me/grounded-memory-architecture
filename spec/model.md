# 경험 기반 기억 관리 아키텍처 — 공개 초안 0.1

상태: 검토용 초안. 표준화 기관의 승인이나 구현 간 상호운용 입증을 뜻하지 않는다. 공개 명칭은 Grounded Memory Architecture(GMA)다. 이 문서의 **필수**, **금지**, **권고**, **선택**은 각각 RFC 2119의 MUST, MUST NOT, SHOULD, MAY에 대응한다.

## 1. 무엇을 정의하는가

이 아키텍처는 경험 기록에서 기억을 형성하고, 기억과 관계를 근거에 따라 수정하며, 사람이 위키로 현재 이해를 탐색하도록 하는 관리 방식이다. 자연어의 참을 자동으로 판정하는 논리 체계나 뇌 전체의 인지 이론이 아니다. 저장 기술, AI 모델, 화면, 검색 알고리즘에 독립적으로 구현할 수 있어야 한다.

핵심 원칙은 **원본은 경험의 이력으로 남기고, 현재 이해는 기억과 관계로 갱신한다**는 것이다. 기록의 수, 반복 빈도, 조회 빈도를 지식의 정확성과 동일시하지 않는다. 단기/장기는 시스템에서의 역할 이름이다. 오래 보존한 원본은 생물학적으로 단기기억이라는 뜻이 아니다.

## 2. 최소 구조

| 기록 | 역할 | 반드시 남기는 것 |
| --- | --- | --- |
| input | 경험·회의·연구·실행의 원본 | 식별자, 본문, 해시, 경험 시점과 등록 시점, 출처, 사건 집단, 상태 |
| memory | 현재 기억할 의미 | 식별자, 온전한 문장·문단·절차, 종류, 적용 맥락, 버전, 채택 상태, 재검토 상태 |
| link | 출처 연결 또는 기억 사이의 관계 | 식별자, 끝점, 관계 종류, 적용 맥락, 근거 구간, 검토자와 이유, 버전, 상태 |
| change | 원인 있는 갱신 | 요청 식별자, 변경 전 버전, 행위자, 시점, 이유, 변경 내용, 결과 |

수치와 검색 색인, 화면용 페이지는 파생 결과다. 별도로 편집하는 정본을 만들지 않는 것을 권고한다. 기억은 한 문장일 필요가 없다. 부정·조건·예외를 포함해 별도로 검토하고 갱신할 수 있는 의미 단위여야 한다.

## 3. 연결 경계

1. input→input 관계망은 **금지**한다. 원문에 들어 있는 URL과 인용은 원문으로 보존할 수 있지만 이 프로파일의 지식 그래프 간선으로 승격하지 않는다. 같은 사건이라는 정보는 origin_group으로 식별한다.
2. input→memory는 context, supports, opposes의 직접 출처 연결이다. 원본의 어느 구간을 어떤 의미로 사용했는지 되짚을 수 있어야 한다. 원본과 기억의 탐색은 화면에서 양방향으로 제공할 수 있다.
3. memory→memory는 장기기억 내부 그래프다. 관계의 의미와 방향을 기록한다. 하이퍼링크는 이 관계를 사람이 탐색하는 표현이다. 단순한 URL 문자열만으로 관계의 의미나 근거가 성립하지 않는다.
4. 관계 자체도 잘못될 수 있다. 기억의 본문을 바꾸지 않고 관계만 철회할 수 있어야 한다. 관계의 basis는 원본의 정확한 구간을 가리킨다.

| 관계 | 의미 | 변경 영향 방향 |
| --- | --- | --- |
| context | 출처 또는 설명 맥락 | input→memory; 신뢰도 집계 없음 |
| supports | 같은 조건에서 대상을 지지 | source→target |
| opposes | 같은 조건에서 반례 또는 반박 | source→target |
| requires | source가 적용되려면 target이 필요 | target→source |
| related | 함께 탐색할 가치가 있음 | 진실성·검토 상태 전파 없음 |
| revises | source가 target의 의미를 정정 또는 대체 | target을 재검토; 자동 전면 철회 금지 |

기억의 ID가 바뀌지 않아도 의미가 바뀌면 새 버전을 남기는 것이 필수다. 다른 주장이 되는 분리·병합에는 새 ID와 이전 기억에 대한 정정 관계를 사용한다. revises 관계만으로 이전 기억을 자동 폐기하면 적용 범위의 부분 중첩을 잃을 수 있다.

## 4. 맥락과 상태

context에는 scope, condition, valid_from, valid_until이 있다. 조건은 자연어로 유지한다. 같아 보인다는 이유로 서로 다른 조건을 합치는 것은 금지다. 최초 프로파일에서는 구조적으로 같은 context만 같은 집계에 포함한다. 의미상 동일한 조건의 정규화는 별도 검토가 필요하다.

시점은 시간대가 있는 RFC 3339의 제한 프로파일이다. 윤초와 알 수 없는 오프셋 -00:00은 이 초안에서 허용하지 않는다. 버전 정수는 0~9007199254740991 범위이며 기록 버전은 1부터 시작한다. JSON Schema의 format 주석만 믿지 않고 실제 날짜와 시간대의 유효성을 검사한다.

memory.kind는 observation, belief, principle, goal, procedure, question을 구분한다. state는 candidate, current, superseded, withdrawn이다. review_required는 현재 근거와 의존을 아직 다시 검토해야 한다는 뜻이다. current와 review_required=true는 이전에 채택했지만 변경 후 검토가 필요한 기억이다. current가 참이라는 뜻도, observation이 무오류라는 뜻도 아니다.

목표·미션·원칙의 효력과 이를 달성하는 수단의 경험적 지지는 구분하는 것이 필수다. 실행 실패는 방법이나 전제를 반박할 수 있지만 목표를 자동으로 폐기하지 않는다. 자동 수치로 회사의 의도를 바꾸지 않는다. 채택 권한은 배포 환경의 정책이 정하며 검토자 문자열 자체는 인증이나 권한 증명이 아니다.

## 5. 출처와 이력

input 본문·출처·경험 시점·사건 집단·본문 해시는 동일 ID에서 불변이어야 한다. 정정한 원본은 새 input으로 기록한다. 새 원본과 이전 원본의 버전 대응은 외부 출처 메타데이터로 관리할 수 있지만 input 간 그래프 관계로 만들지 않는다. 잘못된 자료는 withdrawn으로 표시하며 연결된 기억과 관계를 재검토한다.

본문 해시는 정규화하지 않은 UTF-8 본문의 SHA-256이다. 구간은 Unicode 코드 포인트 기준 start 포함, end 제외이고 quote와 정확히 일치해야 한다. JS의 UTF-16 오프셋을 그대로 쓰는 것은 금지다. 근거는 input ID와 해시를 고정한다. 실제 파일의 원본 바이트 보존은 선택적인 외부 보관 계약이며 이 텍스트 프로파일의 해시와 혼동하지 않는다.

origin_group은 같은 경험의 복제·재인용을 묶는다. null은 독립성을 확인하지 못했다는 뜻이다. 서로 다른 ID나 다른 표현으로 된 요약을 독립 경험으로 세는 것은 금지다. 해시가 다르다는 사실도 독립성의 증명이 아니다.

불변 보존은 접근 권한을 영구 보장한다는 뜻이 아니다. 법적 삭제·권한 철회 시 원문 접근과 파생 노출을 제한하고 필요한 최소 삭제 표시만 보존하는 정책이 우선한다. 일반 수정과 법적 삭제를 구분한다.

## 6. 새 경험으로 갱신하는 과정

1. 원본을 등록하고 기존 기억 및 원자료의 관련 구간을 찾는다.
2. 새 입력을 지지, 반박, 조건 추가, 정정, 새 기억, 맥락 보존, 미확인으로 해석한다. 이 단계는 의미 판단이며 형식 검사로 대체할 수 없다.
3. 기존 기억·관계를 수정하거나 후보를 생성하고 정확한 출처 구간을 연결한다. 모든 문장을 자동으로 기억으로 승격하지 않는다. 긴 논증은 원본에 남기고 필요한 기억에 연결한다.
4. 갱신 요청은 예상 버전과 고유 request_id를 포함한다. 원본 등록, 기억·관계 갱신, 변경 기록과 영향 상태를 하나의 원자적 변경으로 반영하는 것이 필수다.
5. 변경된 전제에서 영향을 받는 기억을 찾아 review_required로 표시한다. 자동으로 거짓이나 확률 감소를 선언하는 것은 금지다. 순환 그래프에서는 방문 집합으로 종료한다.
6. 검토는 변경된 원본과 상반된 근거, 적용 조건, 의존 경로를 확인한다. 최신 근거 집합의 검토 토큰, 검토자와 이유를 기록한다. 검토는 별도 요청으로 처리한다. 순환 의존은 집합을 함께 검토할 수 있지만 집합 밖 미검토 전제를 최신 근거로 취급하지 않는다. 토큰 일치는 최신성 확인이며 의미의 정확성 보증이 아니다.

같은 request_id와 같은 내용의 재시도는 기존 결과를 반환해야 하며 중복 집계를 금지한다. 같은 request_id의 다른 내용은 거부한다. 시간초과 뒤 무조건 다시 실행하지 않고 요청 결과를 조회할 수 있어야 한다. 동시 수정 충돌은 덮어쓰지 않고 재검토한다.

## 7. 변화와 설명 가능한 수치

독립 지지·반박 집단 수는 input→memory의 검토된 current 관계에서만 계산한다. 입력이 withdrawn이거나 관계의 context가 대상 기억과 다르거나 origin_group이 미확인이면 집계하지 않는다. 동일 집단이 지지와 반박 양쪽에 있으면 conflict_groups로 분리한다. memory→memory의 supports를 새로운 독립 경험으로 세는 것은 금지다.

한 input이 다른 context에서 반대 결과를 낼 수 있다. 해당 context별로 별도 연결을 유지한다. 관계 자체의 독립 근거 집계는 relation-signal 확장 프로파일에서 정의하며 코어 집계와 혼합하지 않는다.

활동량, 중요도, 실증 지지, 채택 효력, 검토 최신성은 서로 다른 값이다. 범용 confidence 하나에 합치는 것은 금지다. 사용 빈도는 회상 순위를 돕지만 참의 근거가 아니다. 오래 사용하지 않은 중요한 기억을 자동으로 삭제하는 것은 금지다. 신뢰 확률이나 시간 감쇠는 보정 데이터와 계산 의미가 공개된 확장만 허용한다.

## 8. 검토 최신성

검토 토큰은 해당 기억뿐 아니라 의존 기억의 버전·상태·검토 필요 여부, 관련 관계의 버전·상태·근거, 원본의 해시·상태를 포함한다. 새 관계의 추가, 관계 철회, 간접 전제 변경도 검토를 만료시켜야 한다. 기존 근거 ID만 비교하는 것은 불충분하다.

supports/ opposes는 대상의 의존 근거이며 requires는 출발 기억의 전제다. related는 증거 의존에 넣지 않는다. revises는 이전 기억의 검토에 반영한다. 검토 전제에 순환이 있으면 최신성 토큰을 만들 수 있지만 서로가 서로의 독립 근거가 되지는 않는다.

이 코어는 **이미 연결된 근거 집합**의 최신성을 보장한다. 아직 연결되지 않은 새 문서까지 자동으로 발견했다는 보장은 없다. 자동 검색 기반 판단을 제공하는 확장은 검색 조건과 corpus_revision을 검토 증명에 추가해야 한다. 후보 발견률과 연결 검토율은 별도 평가한다. 참조 예제는 이 자동 검색 확장을 구현하지 않는다.

## 9. 조회와 저장 기술

조회는 저장이나 전체 동기화를 수행하지 않는 것을 권고한다. 필요한 기억, 연결, 원본 구간만 읽고 오래된 검토와 충돌을 표시한다. 직접 출처가 필요하면 원본도 검색한다. 그래프 탐색이 원문 검색을 대체해야 한다는 가정은 없다.

일반 페이지 조회에서 전체 원본 본문을 파싱하거나 모든 기억의 검증을 반복하지 않는 것을 권고한다. 배포 구현은 버전·관계 색인으로 국소 변경을 처리한다. 광범위 변경은 durable 작업 큐로 처리하되 미완료 동안 이전 검토를 최신으로 표시하지 않는다. DB·검색 색인·벡터 저장소를 무조건 분리하거나 특정 그래프 DB를 요구하지 않는다.

내보낸 전체 교환 파일의 적합성 검사와 운영 페이지의 국소 조회는 다르다. 이 저장소의 참조 검사기는 교환 파일 전체를 검사하며 운영 서버 성능의 근거가 아니다.

## 10. 적합성 수준과 확장

- **표현 적합성:** 스키마, ID, 끝점, 원본 해시·구간, 맥락, 검토 토큰, 연결 경계가 유효하다.
- **전이 적합성:** 불변 입력, 버전 증가, 충돌 거부, 원자적 결과, 중복 요청, 영향 전파, 검토 만료를 만족한다.
- **배포 적합성:** 영속성, 인증·권한, 삭제·복구, 작업 완료, 실제 화면과 질의 결과를 입증한다.
- **의미적 유효성:** 원본에서 의미를 올바르게 추출하고 조건·부정·반례를 보존했음을 실제 사용 평가로 입증한다.

앞의 두 수준이 뒤의 두 수준을 대신하지 않는다. 공개된 참조 전이 함수는 메모리 내 동작이므로 DB 충돌 복구나 인증을 입증하지 않는다.

extensions는 이름공간이 있는 별도 객체에만 둔다. 코어의 unknown 필드나 관계 종류를 조용히 무시하는 것은 금지다. 새 핵심 관계는 끝점, 방향, 조건, 집계, 변경 영향과 반례를 명시하고 새 버전의 적합성 사례를 추가한다. 기존 단기기억 연결 경계를 바꾸는 것은 호환되는 확장이 아니다.

## 11. 공개 발전 절차

초안에는 연구 근거, 반대 근거, 명세, 스키마, 성공·실패 사례, 참조 검사기를 함께 공개한다. 예제에는 합성 자료만 사용한다. 외부 두 구현의 왕복 교환과 전이 적합성, 실제 위키의 의미 평가 전에는 안정 표준이나 최고 성능으로 표시하지 않는다. 공개 명칭의 확정은 안정 표준 승인이나 호환성 인증과 구별한다.
